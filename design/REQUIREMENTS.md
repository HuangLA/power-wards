更新日期：2026-09-23（本机存储架构同步）

本文是早期需求快照；当前需求真源为根目录 `../REQUIREMENTS.md`。本文件保留历史讨论并同步当前存储架构摘要，不替代最新需求或实现状态。

## 1. 产品定位与范围

### 已确认

- 产品是 Dota 2 Observer Ward（侦察守卫）眼位编辑器，用于社区传播个人、朋友或职业选手分享的眼位资料。
- 项目已有完整地图 `Game_map_7.41.jpg`，尺寸为 **8909 × 8424**。
- 同一核心应用支持浏览器网页端和桌面客户端，采用中文界面。
- 首版本地使用，不包含账号、云业务后端、云同步、在线分享链接或多人协作；网页端由本机 Node 服务保存文件。
- 网页与桌面各自保存本地资料，不自动同步；通过文件导入、导出交换 Profile。

### 当前实现状态

项目中的 `index.html`、`style.css`、`data.js`、`package.json`、`server.js` 为早期未验证骨架，`map-preview.png` 为检查地图时生成的预览。它们不代表本文需求已经实现或已验证，也不能作为需求依据。早期自动保存、截图随文件分享、标签一律 AND 等设想不替代本文确认的规则。

本次仅创建需求文档，不修改已有代码、不安装依赖、不启动服务、不清理已有文件。

## 2. 界面与信息组织

### 已确认

采用三栏布局：

| 区域 | 内容与行为 |
| --- | --- |
| 左侧 | 当前 Profile 切换与管理，以及分类、标签筛选 |
| 中心 | 大地图和可点击的眼位标记；筛选直接控制地图上眼位的可见性 |
| 右侧 | 仅选中具体眼位时出现可编辑详情；上方上传、显示本地游戏截图，下方编辑颜色、分类、自定义标签和详细文字说明 |

新增眼位时，底部弹出基础分类面板，快速设置阵营与进攻/防守用途。分类须以第 3 节的独立组合记录，不得因界面选择方式产生未选择的组合。

自定义标签用于整理与筛选，详细说明承载具体操作，例如：插眼前需砍树、插眼后砍哪棵树扩大视野、适用时机及其他特殊条件。

### 建议，尚非明确要求

- 两侧面板可收起；打开详情时避免地图布局跳动。
- 筛选使用正向显示选项，并显示结果数量、提供清除筛选入口。
- 布局与缩放切换应服务于查看目标及周边眼位。

## 3. 分类与筛选语义

### 已确认

一个眼位可以多重归类，分类是以下四种独立的阵营与用途组合，允许任意多选：

1. 天辉进攻
2. 天辉防守
3. 夜魇进攻
4. 夜魇防守

例如，眼位同时选择「天辉进攻」和「夜魇防守」，不自动获得「天辉防守」或「夜魇进攻」分类。数据应保留组合关系，不能只分别保存阵营集合与用途集合后计算笛卡尔积。

筛选阵营与用途时，两项条件必须在眼位的**同一个已选组合**中命中。因此上述眼位在「天辉 + 防守」筛选下不可见，在「天辉 + 进攻」或「夜魇 + 防守」下可见。

### 当前建议

同维度多选采用任一匹配，跨维度同时满足。实现时可理解为：存在一个已选分类组合，其阵营命中所选阵营之一，同时其用途命中所选用途之一；未限定的维度不参与约束。这是建议规则，仍需在实现前定稿。

### 待确认

- 自定义标签多选使用 AND（全部包含）还是 OR（任一包含）。不得假定早期代码的全部标签同时命中已获确认。
- 标签与分类条件的最终组合规则，以及筛选状态切换 Profile 时是否保留。

## 4. Profile 与保存语义

### 已确认

- 地图每次仅显示一个当前 Profile，不能叠加多个 Profile 的眼位。
- 用户可新建自己的 Profile，或导入朋友、职业选手的 Profile。
- 任意 Profile 都可直接编辑、保存、另存为；无需先复制，不设只读限制。
- **保存**：将当前修改更新到当前 Profile。
- **另存为**：将当前内容保存为新 Profile，保留原 Profile 的已保存版本。
- **导入**：创建独立的本地 Profile 副本，不改发送者资料，避免无提示覆盖已有 Profile。
- 核心功能为新建、切换、导入、保存、另存为、导出。
- 修改后显示未保存标记；切换 Profile 或关闭时须提供离开保护，供用户保存、放弃修改或取消离开。不能用自动保存替代明确的保存语义。

### 平台约束与待设计事项

应用内 Profile 切换可以实现自定义「保存 / 放弃修改 / 取消」三选项。桌面关闭也应按该语义设计。

网页关闭或刷新受浏览器限制：不能保证自定义三按钮关闭弹窗，也不能保证页面退出时完成异步保存。网页应在浏览器允许的范围内提供未保存离开警告；具体离开保护、保存失败处理和恢复机制待设计，不能承诺网页关闭时一定出现自定义三选项。如果引入恢复草稿，其含义必须区别于用户明确保存的 Profile。

### 建议与待确认

- 重命名、删除 Profile 为管理建议。
- 新建、导入等可能离开当前修改内容的操作建议复用离开保护。
- 另存为后的当前 Profile、导出未保存修改还是已保存版本、命名约束及异常退出恢复细节待设计。

## 5. 本地截图与 JSON 分享

### 已确认

首版通过 JSON 文件导入、导出 Profile。

| 分享文件应包含 | 分享文件不包含 |
| --- | --- |
| 全部文本信息，尤其是详细说明 | 图片二进制、Base64 图片或图片打包内容 |
| 眼位位置、颜色、分类、自定义标签 | 本机图片文件内容 |
| 必要 Profile 元数据、格式版本与地图版本 | 不要求携带本机图片路径 |

截图仅在当前设备本地保存，不随分享文件传播。接收者导入后自行上传自己的游戏截图。导入、导出必须完整保留约定分享的文字与眼位信息，不能因为不分享截图而遗漏说明。

### 待设计

- JSON 的具体字段、标识符、版本迁移和校验规范；本文表格是内容要求，不是既有接口。
- 同名 Profile、重复导入、格式或地图版本不一致的处理策略。
- 截图支持格式、数量与大小限制，以及本地文件生命周期。
- 对旧地图版本显示提醒是建议；不应在未定义坐标迁移规则时静默迁移眼位。

## 6. 地图交互与坐标

### 已确认

| 操作 | 行为 |
| --- | --- |
| Ctrl + 鼠标左键点击地图位置 | 新增眼位，并进入基础分类流程 |
| 左键点击已有眼位 | 选中并打开右侧详情，立即聚焦并放大眼位附近 |
| 地图右键 | 恢复全图视图 |
| 鼠标滚轮 | 缩放地图 |
| 左键按住拖动 | 平移地图 |

- 拖动不能误触点击、选择或新增；应正常区分点标记、背景拖动与 Ctrl 新增。
- 新增业务逻辑与触发手势解耦，未来可改为双击，但当前不启用双击新增。
- 眼位保存地图相对坐标，缩放、拖动及视口尺寸变化后仍对应原地图位置。
- 点击眼位后的具体放大倍率待体验确定，讨论中提及的 50% / 60% / 70% 仅是示例，不是确定参数。

### 建议，待实现时评估

- 保留可见的添加按钮。
- 点击眼位采用固定目标缩放，当前已更近时不缩回。
- 右键恢复全图后保留当前选中眼位与详情。
- 滚轮缩放以指针为中心。
- 删除眼位、移动眼位和删除撤销均为建议，尚未逐项确认。

### 待调参数

聚焦目标倍率、最小/最大缩放、滚轮步长、聚焦动画、点击与拖动阈值、标记尺寸、边界平移策略及重叠标记处理待评估。Ctrl 点击标记等手势冲突的优先级须明确，避免误新增。

## 7. 已认可的技术路线

- **React + TypeScript + Vite**：构建共用界面与业务逻辑。
- **Electron**：作为桌面客户端外壳。
- **网页存储**：页面通过版本化 API 调用本机 Node 服务，将 Profile 和截图保存到本机数据目录；旧 IndexedDB 仅用于首次迁移。
- **桌面存储**：应用数据目录中的文件存储。
- 通过统一存储接口隔离平台差异，使 Profile 编辑、分类筛选、地图交互和 JSON 分享逻辑复用。
- 本机网页服务同时提供 UI 与存储 API，仅绑定本机回环地址；Electron 使用受控 IPC。未来公开托管需另接云端 API、登录认证和服务端用户隔离。
- 网页与桌面存储互相独立，文件分享负责显式交换资料。

### 大图方案建议

对原始大图分层切片，按视野与缩放层级加载，眼位作为独立覆盖层渲染。相对坐标始终基于完整原地图，不随切片层级变化。

具体切片工具或地图渲染库、切片尺寸、层级倍率、缓存、构建产物与加载策略均待实现时评估。当前未完成性能验证，不宣称已解决大图性能问题。

### 接口与数据设计方向（非既有接口）

存储抽象应覆盖 Profile 列举、读取、明确保存、另存为、导入持久化以及本地截图读取与保存。领域数据应区分可分享文本/分类/坐标与不可分享的本地截图资源，并独立维护编辑态及未保存状态。具体 TypeScript 类型、文件结构与 JSON 字段待设计。

## 8. 分阶段实现建议（仅计划，不执行）

1. **规格定稿**：确认标签规则、未保存离开保护、导入冲突、导出编辑态、截图约束及建议功能范围；定义数据格式与存储接口。
2. **共用核心与地图原型**：建立 React / TypeScript / Vite 结构；评估大图加载或切片方案；验证相对坐标、缩放平移、选择聚焦与 Ctrl 新增。
3. **Profile 与编辑流程**：实现单 Profile 展示、分类面板、详情编辑、本地截图、正确筛选及明确保存/另存为；网页接入本机文件服务。
4. **文件交换与数据保护**：实现不带截图的 JSON 导入导出、校验与独立副本创建，完成未保存提示和平台允许的离开保护。
5. **桌面适配**：接入 Electron 与应用数据目录存储，复用核心逻辑，验证桌面关闭保护及与网页的文件互通。
6. **验证与交付**：执行核心验收，评估大图性能和边界交互；提供本机网页服务、桌面构建及本地使用说明。性能结论以实测为准。

## 9. 核心验收标准

| 编号 | 可验证条目 |
| --- | --- |
| A01 单 Profile | 准备两个含不同眼位的 Profile，切换后地图仅显示当前 Profile 符合筛选的眼位，不叠加前一个 Profile。 |
| A02 任意 Profile 可编辑 | 新建及导入的 Profile 均可直接修改颜色、分类、标签、说明和本地截图，无需先复制；保存后重新读取仍保留修改。 |
| A03 保存与另存为 | 保存更新当前 Profile；另存为创建新 Profile，原 Profile 的已保存内容不被覆盖。 |
| A04 组合筛选 | 对仅含「天辉进攻 + 夜魇防守」的眼位，天辉进攻、夜魇防守条件分别命中，天辉防守、夜魇进攻条件均不命中；覆盖四种分类及任意多选，不产生交叉误匹配。多选细节按定稿规则补充用例。 |
| A05 坐标稳定 | 在地图不同位置新增眼位，多次缩放、拖动、聚焦、恢复全图及调整视口后，标记仍落在同一地图地物上；保存后重载、导出再导入亦保持位置。 |
| A06 手势区分 | Ctrl 点击地图新增一次并出现底部分类面板；点击已有眼位打开详情并聚焦；拖动不新增、不误选；滚轮缩放与右键恢复全图正常；双击不触发专门的新增流程。 |
| A07 详情与本地截图 | 未选中眼位时不显示右侧详情；选中后上方显示截图、下方可编辑各字段；本地保存并重启后截图仍可读取。 |
| A08 JSON 完整与无图片 | 用包含中文、换行、特殊字符说明、多分类及多标签的 Profile 导出并在另一端导入，所有分享文本、位置、颜色、分类、标签及必要元数据按格式约定还原；检查文件不含图片内容或打包图片，不依赖发送者本机图片路径。接收端自行上传截图。 |
| A09 导入独立性 | 导入创建独立 Profile，不无提示覆盖已有资料；本地编辑导入结果不影响来源 Profile 或发送者资料。同名、重复及版本冲突按定稿策略测试。 |
| A10 未保存提示 | 修改显示未保存标记；应用内切换时保存可持久化后切换，放弃恢复已保存内容后切换，取消则保留当前编辑状态。桌面关闭按同样语义验证；网页关闭按浏览器允许的离开警告及最终恢复方案验收，不要求自定义三按钮关闭弹窗。 |
| A11 跨端复用 | 网页与 Electron 使用同一界面和核心业务逻辑，通过本机 HTTP API 与 Electron IPC 分别写入本机文件；两端导出 JSON 可互相导入，且本地数据不会自动同步。 |
| A12 大图验证 | 使用真实 8909 × 8424 地图，记录首次加载、缩放、平移及眼位叠加表现；若采用切片，验证视野/层级加载和相对坐标对齐。具体性能阈值待评估后制定，不能提前声称通过。 |

## 10. 实现前待确认清单

- 分类同维度/跨维度多选建议是否采纳；自定义标签 AND/OR 及与分类组合方式。
- 聚焦倍率、大图切片与性能目标、手势冲突优先级。
- 网页离开保护及恢复方案、保存失败处理、导出未保存内容的语义。
- JSON 字段规范、同名与重复导入、地图/格式版本不一致处理。
- 截图格式/大小/数量限制及本地资源管理。
- 是否采纳可收起侧栏、可见添加按钮、重命名/删除 Profile、移动/删除眼位及撤销等建议。

以上待定项不应被早期骨架的现有行为默认决定。
